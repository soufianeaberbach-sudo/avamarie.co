# Ava Marie contact — owner activation and recovery guide

**Phase A code only. No deployment, DNS change, account configuration, real email,
KV creation or production secret operation was performed by this implementation.**
The commands below are for Phase B, **after explicit owner approval**. A merge or a
passing test does not activate email. Do not merge into an automatically deployed
branch until the owner has approved and prepared activation.

## 1. Confirm the Cloudflare project and deployment path

Work only in `soufianeaberbach-sudo/avamarie.co`, Worker **avamarie**. Confirm the
account and existing `avamarie.co` domain association in Workers & Pages. Do not
create a similarly named Worker in another account or attach the portfolio's
resources. Preserve the existing domain routing and static site settings unless
an approved activation change is required.

```sh
npm ci
npm run build
npm test
# Install the test browser if needed (or set CHROMIUM_PATH to an installed Chromium).
npx playwright install --with-deps chromium
npm run test:browser
npx wrangler deploy --dry-run
npx wrangler whoami
```

Requires Node 22.18+ (tested with 24), Python 3, pinned Wrangler 4.158.0. The build
remains `scripts/build.py` from `index.html`; `scripts/stage_assets.py` stages the
public allowlist into `dist/`. Wrangler runs `npm run build` automatically.
Never set `assets.directory` back to `.`. Keep the committed selective
`run_worker_first` routes for `/api/*`, `/admin`, `/admin/*`, `/index` and `/index/`.
The Worker handles API methods before static routing, canonical legacy redirects,
and real Admin SPA deep links. Other static requests keep asset-first serving;
`not_found_handling:404-page` preserves genuine 404s without a global SPA fallback.
The seven public entry points all use `/js/contact.js`. This repository runs
exclusively on Cloudflare; no retired hosting or Identity widget is required.
See [the migration audit](CLOUDFLARE-ONLY.ar.md) for authentication findings and
external services that the owner must disconnect separately.

Review current automatic deployment hooks before merging this PR. For a Workers
Builds project use `npm ci` then `npx wrangler deploy` with its build command
configured here; avoid another pipeline overwriting the result with assets-only
uploads. No account-level custom domains or zone routes are added by this PR. Confirm the existing
custom domain points to Worker `avamarie`, and that both API and static paths use
that Worker. `/index` and `/index/` return 301 to `/` preserving the query string;
Admin routes such as `/admin/orders` and `/admin/models/AM-001` render the existing
app directly and survive refresh. Missing Admin bundles and unknown URLs return
404, not the Admin shell. Add any future real Admin routes to the scoped Worker
matcher when changing the compiled app router. If `www.avamarie.co` redirects
to the apex, preserve the redirect.
Do not create/change domain or DNS records until separately approved.

## 2. Configure a dedicated Resend sender

In Resend, add an Ava Marie sending identity (the owner must choose the domain or
subdomain, such as a subdomain of avamarie.co). Do not assume avamarie.co is already
verified. Copy **exactly** the DNS records generated by Resend: the record types,
hostnames, priorities and values for the chosen sending domain/region. Do not
invent SPF, DKIM, MX or DMARC values; do not overwrite existing receiving-mail or
SPF records. Wait until Resend reports **Verified**. Review existing DMARC and
SPF with the domain administrator if changes would conflict.

Prefer a separate, sending-only API key restricted to that Ava Marie domain.
The sender below is a plain mailbox on the verified identity, not a display-name
string. The recipient is **owner input**; this code deliberately supplies none.
The public fallback address `Anwar@sweetthreadsltd.com` already exists on the
website and is not implicitly selected as the backend recipient. Confirm mailbox
ownership/availability with the owner; this implementation did not verify it.

## 3. Create Ava Marie Turnstile keys

Create a **Managed** Turnstile widget dedicated to Ava Marie. Allow exactly the
hostnames actually serving the form: `avamarie.co`, plus `www.avamarie.co` only if
it serves the form. Do not include arbitrary preview hosts in production. The
client uses action `ava_contact`; Siteverify must return that action and the
exact request hostname. Production only permits HTTPS origins in
`CONTACT_ORIGINS` (apex and www currently declared in Wrangler).

Set the **public site key** as runtime variable `TURNSTILE_SITE_KEY`. The browser
obtains only that value from `GET /api/contact-config` with `Cache-Control:
no-store`; no generated HTML editing or build-time key injection is needed.
Set `TURNSTILE_SECRET` as a secret. Missing any mandatory configuration returns
503; protection is never silently disabled. Keep site/secret keys from the same
widget. Do not use Cloudflare's test keys in production. Existing CSP, if added
outside the repo, must permit Turnstile scripts and frames from
`https://challenges.cloudflare.com` (follow Cloudflare's CSP guidance).

## 4. Create dedicated recovery storage and abuse control

The owner-created namespace `avamarie-contact-enquiries` is already declared in
`wrangler.jsonc` as `CONTACT_ENQUIRIES`, ID
`c0db1995db8743888ccc54d79f033802`. Confirm it belongs to the intended Cloudflare
account at activation; do not create a duplicate or reuse portfolio's `BRIEFS`.
No R2, uploads, queue or automatic resend mechanism is needed. Use isolated

The native Rate Limiting binding is also committed (it is **not KV**):

```jsonc
"ratelimits": [{
  "name": "CONTACT_RATE_LIMITER",
  "namespace_id": "1862459001",
  "simple": { "limit": 20, "period": 60 }

```

`1862459001` is a project-selected positive integer expressed as a string, as
required by Cloudflare's schema. It is not an existing KV namespace identifier,
and no resource creation or deployment was performed to choose it.

`TECHFA`'s visible default-branch tree has no Wrangler config, and the separate

`ratelimits` and `namespace_id` under the owner's repositories returned only the
activation-document example. No conflict with the chosen ID was found in these
accessible configurations; search indexing is not an authoritative inventory.

**Account-wide uniqueness is unverified.** This audit did not enumerate every
live Worker/environment, dashboard-only config, other owner's repository, or
unavailable private config in the Cloudflare account. Matching IDs can share
counters across Workers, so before approved production activation the owner must
check all live rate-limit bindings in that account for `1862459001` (through an
authorized Workers settings/API inventory). If already used by an unrelated
binding, choose another unused positive integer and revalidate this config.
Do not change portfolio/aberbach.co resources to free an ID. The dry run checks
configuration/bundling; it does not establish global uniqueness or live quotas.

This uses Cloudflare's supported native Rate Limiting binding (Wrangler >=4.36).
The Worker hashes `CF-Connecting-IP` for this limiter and never persists the IP
in an enquiry. Twenty attempts per minute per shared IP is a flood screen for an
anonymous form, not an account quota. Corporate/mobile networks can share an IP.
Cloudflare's limiter is **approximate, per Cloudflare location**; it is not a
strict global limit. KV is not used for counters or locks. A missing/failing
limiter fails closed. Observe legitimate 429s and adjust responsibly. Turnstile,
origin checks, bounded JSON, validation and honeypot remain additional controls.

## 7. One authorized end-to-end delivery test

Use a controlled customer email and a distinctive non-sensitive test message
through the real form on `https://avamarie.co/contact/`. Solve Turnstile normally.
Confirm all of the following:

1. Only one POST to `/api/contact`; HTTP 200 JSON contains `ok:true` and reference.
2. UI success is “Thank you. Your message has been submitted successfully.”
3. `enquiry:<reference>` and `accepted:<reference>` are in the dedicated KV.
4. Resend shows the same reference and provider email ID, then delivery status.
5. The chosen recipient actually receives the message (including spam checks).
6. Reply-To points to the controlled customer's address.

A 200 means **Resend accepted** the email, not guaranteed inbox delivery. Check
bounces/delivery in Resend separately. With owner approval test a controlled
failure in isolated staging: data remains in the form, no success, button usable,
and an email failure leaves a recoverable enquiry. Do not break production
credentials to simulate outages. Document test time/reference/status without
publishing customer data. No live delivery test was performed in Phase A.

## 8. Diagnose failures and recover saved enquiries

| HTTP/code | Meaning / checks |
|---|---|
| 400 `validation` | email/message, field types, lengths, control characters, UUID |
| 400 `spam` | honeypot populated |
| 400 `verification` | missing/expired token, action or hostname mismatch |
| 403 `origin` | wrong/missing Origin or cross-site request |
| 405 / 415 / 413 / 408 | method / JSON content type / 16 KiB request / slow body |
| 429 `rate_limited` | wait 60 seconds; inspect limiter traffic |
| 503 `unavailable` | bindings, vars, sender/recipient syntax, expected host, trusted CF client IP |
| 503 `verification_unavailable` | Siteverify timeout/network/provider rejection |
| 503 `storage` | enquiry could not persist, email was not attempted |
| 502 `email_unconfirmed` | enquiry saved; Resend acceptance unknown/failed |

No provider error bodies, secrets, raw IPs or full messages are logged by this
Worker. Logs use fixed events and a reference only. Do not enable request-body
capture or log full KV records. Configure Cloudflare status/error monitoring,
Resend bounce monitoring, and a named owner to check saved enquiries **daily**.
There is **no automatic retry or alert job** in this implementation.

Each enquiry holds only the normalized six fields, reference, timestamp and
`emailState:unconfirmed`. A separate `accepted:<reference>` marker holds the
provider ID and acceptance time, and is authoritative for recorded acceptance.
The initial record is intentionally never relabeled as emailed just because it
was stored. Both keys have a **90-day TTL**; mailbox copies/Resend retention and
any operator exports have separate policies. The owner should confirm this
retention and appropriate privacy disclosure before activation.

Read only from an authorized workstation; do not paste output into public logs:

```sh
npx wrangler kv key list --binding CONTACT_ENQUIRIES --remote --prefix 'enquiry:'
npx wrangler kv key get 'enquiry:<reference>' --binding CONTACT_ENQUIRIES --remote
npx wrangler kv key get 'accepted:<reference>' --binding CONTACT_ENQUIRIES --remote
```

Paginate listings until complete (Cloudflare Dashboard/KV API can also be used).
KV is eventually consistent: allow propagation and recheck. An enquiry without
an accepted marker needs investigation; it does **not** prove email was never
accepted. Search Resend for the exact reference in the subject and inspect
`contact_email_unconfirmed` / `contact_acceptance_marker_failed` events. A timeout
can lose a successful provider response, and a marker write may fail after a real
acceptance. Check Resend before contacting the customer or manually re-sending.
Never delete the recovery record just because a marker is missing.

Resend's idempotency key is `ava-contact/<reference>` and its window is **24
hours**. The browser reuses its UUID only for unchanged retries in the same page
session; the reference is a hash of that UUID and normalized fields, and the
provider payload stays identical. Do not claim exactly-once delivery: refresh,
a new session, changed fields, a changed sender/recipient, or a retry after the
24-hour window can produce a distinct send or a provider conflict. UI blocking
prevents accidental concurrent clicks. KV is not an atomic deduplication lock.

If Resend never accepted it, an authorized operator can recover the six fields
from KV and contact the customer using the verified business mailbox, or resend
via Resend with approval. Preserve Reply-To and use plain text. Record the
manual action in private business operations records and mark provider acceptance
only after confirmed acceptance. There is no public read/recovery endpoint.
Restrict KV account access; delete a customer's records by reference on an
approved erasure request. Retention expiry is a backstop, not a substitute for
monitoring: unattended outages can outlast it.

## Local development and mock testing

`npm test` and `npm run test:browser` use fake provider responses and never send
emails. The Playwright suite starts isolated local Python/static and Wrangler
servers; Wrangler's incomplete production config deliberately returns 503. This
checks asset/API routing and private-file 404s without Cloudflare credentials.

For manual local widget development, copy `.dev.vars.example` to `.dev.vars`.
Use `ENVIRONMENT=development` **only on loopback** with Cloudflare's documented
always-pass testing keys; Siteverify still runs, with its testing hostname
`dummy-key-pass` expected only on localhost/127.0.0.1/[::1]. Production hosts never
use that exception. Add local-only KV and rate-limit bindings using a separate
Wrangler local configuration and its local emulator; do not add fabricated
production IDs to this file. Keep the fake Resend key to exercise the truthful
saved-but-email-unconfirmed path. Automated tests mock storage/limiter/providers
without any key or namespace setup. Preview activation needs a separate Worker,
recipient, keys and storage; it is not implicitly allowed on workers.dev.
